# 2026-11-21 台架联调里程碑

## 当前里程碑

**AT8236 双路电机完成安全短脉冲测试，左右轮前进方向统一。** 小车在支架上测试，两个驱动轮离地；每次只点动一路 200 ms。

- 用户确认右侧实体电机接在 `MOTOR-A`，左侧实体电机接在 `MOTOR-B`。
- `MOTOR-B` 使用 `BIN1=1、BIN2=0` 点动，用户确认左轮向前。
- `MOTOR-A` 最初使用 `AIN1=1、AIN2=0` 时右轮向后。电机线是一体插头，未拆线换序；测试固件改成 `AIN1=0、AIN2=1` 后，用户确认右轮向前。
- 两路点动都由 ST-LINK 虚拟串口执行 `ARM` 后再发送 `A` / `B`。串口回报 `A_DONE; inputs low` 或 `B_DONE; inputs low`；没有发连续运行命令。
- 当前使用的 `firmware/motor_serial_test/` 是临时台架测试固件。启动时四路控制输入先保持低电平；单次点动结束后再次拉低。它不是循迹或视觉控制固件，也没有 PWM 调速、编码器闭环。
- 修改后固件通过 STM32CubeProgrammer 下载校验；无害命令 `HELLO` 收到 `IGNORED; send ARM first`，确认 VCP 收发正常且未触发电机。
- 烧录前读回的 512 KiB Flash 备份保存在本机 `firmware/local-backups/nucleo-f446re-pre-motor-test-20261121.bin`；备份文件不放入 Git 仓库。

- YB-MVP01-V1.0 输出实测：`VADJ 10.37 V`、`5V-OUT 5.13 V`、`3V3-OUT 3.34 V`。

## 异常一：ST-LINK 找不到 STM32 芯片 ID

### 现象

NUCLEO 的 ST-LINK 能被 Mac 识别，目标电压约 3.23 V；但从主 Flash 正常启动、`BOOT0=0` 时，`st-info --probe` 报 `Can not connect to target`，并读到 `chipid=0x000`。这曾被误以为芯片损坏。

### 排查结果

- 把 `BOOT0` 临时拉高后，ST-LINK 可识别 `STM32F446`，芯片 ID 为 `0x421`，512 KiB Flash 可读取。
- STM32CubeProgrammer 读取选项字节为 `RDP 0xAA / Level 0`；PCROP、写保护未启用，排除了读保护配置。
- 当前读回的主 Flash 开头与电机安全待机固件一致。没有证据表明芯片损坏。
- ST-LINK 固件从 `V2J28M18` 更新到 `V2J48M35`。更新后 `BOOT0=0` 的普通连接仍可能失败。
- 稳定可用的恢复方式是 STM32CubeProgrammer **Connect Under Reset**，例如 `-c port=SWD mode=UR freq=100`。该模式成功识别 ID `0x421`、读取选项字节、烧录并校验固件。

### 下次遇到时怎么做

1. 先确认 ST-LINK USB 和目标电压正常；不要因普通连接读到 `chipid=0` 就判断 MCU 已损坏。
2. BOOT0 测试线不需要长期保留；按正常方式连接后，优先使用 CubeProgrammer 的 **Connect Under Reset / `mode=UR`**。
3. 只读检查选项字节，确认 `RDP Level 0`。不要试写或解锁选项字节。
4. 烧录时先关闭电机稳压板和 AT8236 电源，避免复位期间输入悬空导致电机抖动。

**根因状态：**普通连接失败的根因仍未完全定位；已找到可靠的调试和烧录工作方式。不要把“使用 Under Reset 可连接”写成已修复普通连接模式。

## 异常二：电机接入后无命令自行转动，且 MOTOR-A 方向相反

- 早期接上电机、控制脚没有由固件主动确定电平时，右轮曾自行转动。现象与 H 桥控制输入悬空相符，但当时没有捕获到输入脚瞬态电平，故不把推测当成已证明的根因。
- 处理方式：先烧录安全待机/短脉冲固件，启动时主动把 `PB3/PB5/PB4/PB10` 拉低；驱动输入全低时不发电机命令。短脉冲程序必须先收到 `ARM`，5 秒内再收到 `A` 或 `B` 才会点动。
- 右轮 MOTOR-A 用原控制组合 `AIN1=1` 实测向后。因为两根电机线装在一体插头中不便换序，改为软件让 MOTOR-A 使用 `AIN2=1`；未拆插头、未交换电机线。
- 左轮 MOTOR-B 使用 `BIN1=1` 实测向前。修改后重新点动 MOTOR-A，用户再次确认向前。两个轮子方向现已一致。

## 当前接线与固件边界

用户报告已把先前的信号线接回：八路循线板 4 根、MaixCAM2 3 根、AT8236 5 根。复接后的实体针位没有新照片供逐根目视复核。已有针脚记录如下：

| 模块 | 已记录接法 | 当前验证状态 |
|---|---|---|
| AT8236 控制与共地 | `AN1/AIN1 → D3/PB3`；`AN2/AIN2 → D4/PB5`；`BN1/BIN1 → D5/PB4`；`BN2/BIN2 → D6/PB10`；`GND → GND` | 控制脚曾逐个测得 0 V；两路电机短点动通过。最近重新接回整束后仍待再次检查。 |
| YB-MUX04-2.0 I²C | `5V/GND/SCL/D15-PB8/SDA/D14-PB9` | 黑白校准、白底 `0xFF`、八路响应曾通过；重新接回后需重扫 I²C。 |
| MaixCAM2 UART | `U2T/B0 → PA10/USART1_RX`；`U2R/B1 ← PA9/USART1_TX`；`GND → GND` | 过往实际 UART 联调通过；重新接回后尚未复测。 |

当前 NUCLEO 烧录的是电机短脉冲测试固件；它只监听 ST-LINK 虚拟串口 USART2，不读取循线板 I²C，也不读取 MaixCAM2 USART1。因此，接回线束不等于这两条通信链路已重新通过。
